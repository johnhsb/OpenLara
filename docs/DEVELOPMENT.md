크래시 분석, 그동안의 시행착오. 무엇이 바뀌었는지는 [CHANGES.md](CHANGES.md)에 있습니다.

## 1. 작업 원칙

- **브랜치**: `main`은 TR1·TR2 버그 수정용이고 릴리즈는 여기서 냅니다. TR3 전용 신규 기능은 `tr3` 브랜치에서 구현합니다.
  TR3 작업 중 찾은 공용 버그는 `main`에 먼저 커밋한 뒤 `tr3`로 병합합니다. 병합은 `main` → `tr3` 한 방향입니다.
- **원작 동작이 기준**입니다. TRX(GPLv3)는 동작을 확인하는 참고로만 보고 코드를 옮기지 않습니다. 커밋 메시지에 "As the original does"와 원작 함수명(Object_Collision, ItemPushLara, GetHeight 등)을 남겨 근거를 기록합니다.
- **TR1과 TR2 규칙이 다르면 버전으로 분기**합니다 (`level->version & TR::VER_TR1`). TR1 원작과 다른 동작을 TR1에 퍼뜨리지 않습니다 (예: 매복 숨김은 TR2+만).
- **공통 코드는 공통 헤더, 게임 전용은 전용 헤더**: `enemy.h`/`objects.h`는 공용, `enemy_tr1.h`/`objects_tr1.h`, `enemy_tr2.h`/`objects_tr2.h`는 각 게임 전용.
- **커밋은 논리 단위로 나눕니다.** 한 커밋은 한 가지 동작 변화와 그 원인을 설명합니다. 메시지는 영어입니다.
- **원인을 확인한 뒤 고칩니다.** 로그나 수치로 원인을 확정하고, 같은 조건에서 켠/끈 결과를 비교합니다(9장).

## 2. 빌드와 배포

소스는 WSL에 두고, 플레이와 확인은 Windows 실행 파일로 합니다.

| 대상 | 방법 | 결과물 |
|---|---|---|
| Windows x64 | 소스 트리를 Windows 쪽 임시 폴더(예: `%TEMP%\olbuild`)에 복사한 뒤 `src\platform\win\build_msvc.bat` | `OpenLara.exe`, `OpenLara.pdb` |
| Linux / WSL | `src/platform/sdl2/build.sh` (SDL2, GLES3) | `src/platform/sdl2/OpenLara` |
| 웹 | `src/platform/web/build.sh [TR1 폴더] [TR2 폴더]` (Emscripten) | `src/platform/web/out/` |
| macOS | `src/platform/osx/build.sh` (`-d`는 디버그, `-u`는 인텔 겸용) | `OpenLara.app` |

Windows 빌드를 WSL에서 돌리는 순서:

```bash
rm -rf "$WINTMP/olbuild/src" && tar cf - src | tar xf - -C "$WINTMP/olbuild"     # WINTMP=/mnt/c/Users/<사용자>/AppData/Local/Temp
cd "$WINTMP" && /mnt/c/Windows/System32/cmd.exe /c '%TEMP%\olbuild\src\platform\win\build_msvc.bat'
```

- `cmd.exe`는 전체 경로로 부릅니다(WSL의 PATH에 없을 수 있음).
- 배치 파일은 `/Zi /DEBUG`로 빌드해 PDB를 만들고, 로컬 인증서가 있으면 서명합니다.
- **배포**: `OpenLara.exe`와 `OpenLara.pdb`, Linux 바이너리를 게임 폴더에 복사하고 md5로 확인합니다. `main` 빌드는 TR1·TR2 폴더에,
  `tr3` 빌드는 TR3 폴더에 넣습니다. PDB가 실행 파일과 같은 빌드여야 크래시 로그에 함수 이름과 줄 번호가 나옵니다.
- 게임이 실행 중이면 복사가 Permission denied로 실패합니다. 게임을 닫고 다시 복사합니다.

**릴리즈**

- 릴리즈는 `main`에서 냅니다. Windows, Linux x64, 웹 묶음은 로컬에서 만들어 `gh release create <태그>`로 올립니다. 웹 묶음에는 `index.html`, `OpenLara.js`, `OpenLara.wasm`, `serve.py`가 들어갑니다.
- 태그가 올라가면 `.github/workflows/release.yml`이 macOS(Apple Silicon·인텔 겸용, `build.sh --universal`)와 Linux ARM64를 빌드해 같은 릴리즈에 추가합니다. 이미 있는 릴리즈에 다시 올릴 때는 `gh workflow run release.yml -f tag=<태그>`, 태그 없이 돌리면 빌드만 합니다.
- 러너 이름은 GitHub가 주기적으로 없앱니다(`macos-14`가 없어져 작업이 시작도 못 하고 취소된 적이 있음). 작업이 단계 없이 취소되면 러너 이름부터 확인합니다.

## 3. 실행 옵션과 환경 변수

```
OpenLara.exe data/venice.tr2 --pos=73,37376,3840,18944,0 --give=KEY_ITEM_2
```

| 옵션 | 뜻 |
|---|---|
| 첫 인자 (Linux는 `-l`) | 시작할 레벨 파일 |
| `--pos=room,x,y,z,angle` | 라라의 시작 위치, 각도는 도 (Windows, macOS) |
| `--give=item[,item...]` | 시작할 때 인벤토리에 넣을 아이템. `KEY_ITEM_1..4`, `PUZZLE_1..4` 또는 타입 번호(TR2는 1000을 더한 값, 예: 1140) |
| `--activate=index[,index...]` | 레벨 시작 1초 뒤 작동시킬 엔티티 번호 |
| `-d dir`, `-f` (Linux) | 데이터 폴더, 전체 화면 |
| `--high-dpi` (Windows) | 고해상도 DPI 인식 |

| 환경 변수 | 뜻 |
|---|---|
| `OL_NORMAL_MAP=0` | 노멀 맵 끔 |
| `OL_BUMP=<강도>` | 설정 대신 쓸 노멀 맵 강도 |
| `OL_FOG=<시작>,<범위>` | 원경 안개(블록 단위), `OL_FOG=0`은 끔 |
| `OL_FOG_COLOR=<r>,<g>,<b>` | 안개 색 (0..1) |
| `OL_TEXTURE_PACK_MIX=0..1` | 텍스처 팩에서 업스케일 디테일이 원본 위에 보이는 정도 |
| `OL_DUMP_TEXTURES=1` | 레벨의 원본 타일을 파일로 저장 |
| `GALLIUM_DRIVER=llvmpipe` | (WSL, Mesa) 소프트웨어 렌더링. 자동 테스트는 이것으로 돌립니다(5장) |

- 세이브와 설정, 스크린샷: Windows `%APPDATA%\OpenLara\tr1`, `tr2`; Linux `~/.openlara/tr1`, `tr2`; macOS `~/Library/Application Support/OpenLara/tr1`, `tr2`.
- 키: `F` FPS 표시, `F12` 스크린샷(세이브 폴더에 `screenshot_NNNN.jpg`, 저장한 경로는 로그에 남음).
- 화면의 FPS 줄은 로그에도 남습니다: `FPS: 120 DIP: 20 TRI: 4384 RT: 2` (드로 콜, 삼각형, 렌더 타깃 전환 수).

## 4. 테스트 위치

`--pos`와 함께 쓰는, 바닥을 확인해 둔 위치입니다. 새 위치는 9장의 "테스트 위치 함정"을 보고 고릅니다.

| 대상 | 명령행 |
|---|---|
| 빨간 스노모빌 옆 (액션 키로 탑승) | `skidoo.tr2 --pos=12,71168,1024,41000,0` |
| 무장 스노모빌 용병 (우지와 탄약) | `skidoo.tr2 --pos=112,23040,3072,17920,135 --activate=88 --give=87,91,91,91` |
| 석상 창병 둘 (앞의 초록 구역은 산성 웅덩이) | `floating.tr2 --pos=86,31744,-1280,75264,0 --activate=70,71` |
| 석상 검병의 비행 (기둥 위) | `floating.tr2 --pos=1,78336,-5888,52736,270 --activate=2` |
| 석상 검병 (다른 위치) | `floating.tr2 --pos=1,73216,-2816,50688,90 --activate=2` |
| 부유섬 허공 낙하 | `floating.tr2 --pos=1,76288,-3000,57856,180` |
| 바르톨리와 드래곤 | `xian.tr2 --pos=18,47616,-7168,39424,90 --activate=43,45 --give=1140,1147,1147,1147` |
| 얼음 궁전 큰 그릇 | `icecave.tr2 --pos=28,34304,5888,48640,270 --activate=34` |
| 난파선 갑판의 경사 구덩이 (미끄러져 턱 위로 빠져나옴) | `deck.tr2 --pos=84,30619,1905,29595,90` |
| 베니스 (README 예시) | `venice.tr2 --pos=73,37376,3840,18944,0 --give=KEY_ITEM_2` |

- 해상 플랫폼(`rig.tr2`)의 점프 후 잡기 확인 위치: 방 22의 (28772, -5376, 73393)에서 서쪽을 보고 선 자리. 방 23의 턱(y -6912)까지 한 칸짜리 해치를 건너뛰며, 점프 정점에서 손이 턱보다 5만큼만 높아 점프 수치가 조금만 달라도 실패합니다.
- 저택 엔딩은 숨어 있는 적도 남은 적으로 세므로 레벨을 끝까지 진행해야 합니다. 하네스에서는 적을 모두 죽이는 임시 훅으로 확인했습니다.
- 시안 사원과 저택은 레벨 전에 영상(JEEP, END)을 재생합니다. 테스트 폴더에서 `fmv`를 빼면 바로 시작합니다.

## 5. 테스트 하네스

사람이 조작하지 않고 같은 상황을 되풀이해 수치를 재는 방법입니다. 스크래치 폴더는 세션마다 지워지므로 필요할 때 다시 만듭니다.

**구성**

- `src`를 스크래치 폴더에 복사하고, 임시 훅은 그 복사본에만 넣어 Linux 바이너리로 빌드합니다. 저장소의 코드에는 훅을 남기지 않습니다.
- 게임 데이터는 링크로 연결하고 `fmv`는 뺍니다.
- `HOME`을 스크래치 폴더로 바꿔 실제 세이브와 설정을 건드리지 않습니다.
- **WSL에서는 `GALLIUM_DRIVER=llvmpipe`를 명시**합니다. 지정하지 않으면 d3d12(GPU) 경로가 선택될 수 있고, 그 경로의 자동 테스트가 Windows 화면 전체를 멈춘 적이 있습니다. GPU에서의 동작은 Windows 실행 파일로 직접 확인합니다.

```bash
S=<스크래치 폴더>
mkdir -p $S/run $S/home && cd $S/run
for d in audio data music; do ln -sf <TR2 게임 폴더>/$d $d; done     # fmv는 일부러 뺌
HOME=$S/home GALLIUM_DRIVER=llvmpipe timeout 30 stdbuf -oL $S/t/platform/sdl2/OpenLara -l data/rig.tr2 > $S/run.log 2>&1
```

**자주 쓰는 임시 훅** (모두 환경 변수로 켜고, 끝나면 지움)

| 훅 | 넣는 곳 | 하는 일 |
|---|---|---|
| 고정 시간 간격 | 플랫폼 `main`의 프레임 시간 계산 | 프레임 시간을 1/30, 1/60, 1/120, 1/144초로 고정해 프레임률별 결과를 비교 |
| 시작 위치 | `Lara` 초기화 | Linux 빌드에는 `--pos`가 없어 환경 변수로 방·좌표·각도를 줌 |
| 입력 주입 | `Lara`의 `networkInput` | 시간대별 입력 (`"1.5-2:128,4-8:8"`, 값은 `Character::Key` 비트) |
| 상태 출력 | `Lara::update()` 머리 | 위치·속도·상태·애니메이션 프레임을 매 틱 출력 |
| 최신 세이브 로드 | `level.h`의 `if (loadSlot > -1 && nextLevel == TR::LVL_MAX) {` 앞 | `loadSlot = saveSlots.length - 1` |
| 엔티티·애니메이션 덤프 | `level.h`의 `initEntities()`에서 `initCarriedItems();` 뒤 | 출력 후 `exit(0)`. TR2 타입은 1000 오프셋을 반영해 이름을 붙임 |
| 바닥 덤프 | 레벨 로드 뒤 | 방의 칸별 바닥 높이, 아래 방으로 통하는 칸은 `v방번호` |
| 영상 건너뛰기 | 영상 재생 시작 | 레벨 전 영상에서 멈추지 않게 함 |
| 화면 저장 | `Game::render()` 뒤 | `glReadPixels`로 지정 시각의 프레임 저장 |

- 강제 입력은 `Input::state`를 직접 읽는 코드(스위치, 퍼즐 판정)에는 닿지 않습니다. 인벤토리도 조작할 수 없습니다.
- 프레임률에 따라 달라지는 문제(점프 높이, 잡기)는 30/60/120/144 Hz 네 가지로 모두 확인합니다.

**레벨·세이브 파일을 직접 읽기**

위치를 고르거나 원인을 좁힐 때는 게임을 돌리지 않고 레벨 파일을 읽는 편이 빠릅니다.

- TR2 레벨: 버전(4) → 팔레트(768 + 1024) → 텍스처 타일 수 n과 타일(n × 65536, n × 131072) → 4바이트 → 방 수.
- 방: `x, z, yBottom, yTop`(각 int32), 데이터 워드 수와 데이터, 포털(32바이트), `zSectors, xSectors`와 섹터(8바이트), 조명(24바이트), 정적 메시(20바이트), 대체 방, 플래그. 섹터 인덱스는 `x * zSectors + z`.
- 방 뒤: 바닥 데이터, 메시, 애니메이션(32), 상태 변화(6), 디스패치(8), 명령(2), 메시 트리(4), 프레임(2), 모델(18), 정적 메시(32), 오브젝트 텍스처(20), 스프라이트(16, 8), 카메라(16), 사운드 소스(16), 박스(8), 오버랩(2), 존(박스 × 20), 애니메이션 텍스처, 엔티티(24바이트: 타입, 방, x, y, z, 각도, 밝기 2개, 플래그).
- 엔티티 타입은 코드에서 `TR2_TYPES_START`(1000)를 더한 값입니다.
- 스크립트 이름을 `types.py`처럼 표준 모듈과 같은 이름으로 지으면 `import re`부터 실패합니다.

## 6. 크래시 분석

Windows 빌드는 크래시가 나면 실행 파일 옆에 두 파일을 남깁니다.

| 파일 | 내용 |
|---|---|
| `OpenLara.log` | 실행 로그 끝에 `*** CRASH: exception 0x… at …`, 읽거나 쓰려던 주소, 호출 스택(함수 이름과 소스 줄 번호) |
| `OpenLara.dmp` | 미니덤프(`MiniDumpNormal`): 모듈 목록, 스레드, 각 스레드의 스택. 힙은 없음 |

**순서**

1. **게임을 다시 실행하기 전에** 두 파일을 다른 곳에 복사합니다. 다시 실행하면 로그가 덮어써집니다.
2. 로그의 호출 스택 맨 위를 봅니다. OpenLara 함수가 있으면 그 줄에서 시작합니다.
3. 스택에 OpenLara 함수가 없고 `Drv…`, `D3D11…` 같은 이름만 있으면 드라이버 스레드에서 난 것입니다. 덤프의 모듈 목록으로 각 주소가 어느 DLL인지 확인합니다.
4. 주소를 직접 풀 때는 `llvm-symbolizer --obj=OpenLara.exe --relative-address 0x<오프셋>`(오프셋 = 주소 − 실행 파일의 로드 주소, 같은 빌드의 PDB가 옆에 있어야 함).

**덤프에서 모듈과 예외 스레드 읽기**

```python
import struct
d = open('OpenLara.dmp', 'rb').read()
sig, ver, n, rva = struct.unpack_from('<IIII', d, 0)
name = lambda r: d[r + 4 : r + 4 + struct.unpack_from('<I', d, r)[0]].decode('utf-16le')
for i in range(n):
    t, sz, r = struct.unpack_from('<III', d, rva + i * 12)
    if t == 4:                                   # 모듈 목록: 108바이트씩
        for j in range(struct.unpack_from('<I', d, r)[0]):
            base, size, chk, ts, nr = struct.unpack_from('<QIIII', d, r + 4 + j * 108)
            print('%016x %08x %s' % (base, size, name(nr)))
    if t == 6:                                   # 예외: 스레드, 코드, 주소
        tid, pad, code, flags, rec, addr = struct.unpack_from('<IIIIQQ', d, r)
        print('exception thread %d code %x at %x' % (tid, code, addr))
    if t == 3:                                   # 스레드 목록: 48바이트씩 (id, …, 스택 시작·크기·위치, 컨텍스트)
        pass
```

- 덤프에는 힙이 없어 **라라의 위치 같은 게임 상태는 복원할 수 없습니다.** 스택에 남은 값으로 추정해 봤으나 근거가 되지 못했습니다. 위치가 필요하면 상태 출력 훅이나 크래시 직전의 스크린샷을 씁니다.
- 메인 스레드는 스택에 `WndProc`, `Game::frameBegin` 같은 실행 파일 주소가 가장 많은 스레드입니다.

**사례**

| 증상 | 원인 | 구분하는 법 |
|---|---|---|
| 스노모빌을 몰다가 GPU 드라이버 안에서 크래시 | `Core::setBasis`가 포인터만 보관하는데 함수 스택의 임시 배열을 넘김. 게임 코드의 버그 | 크래시 스레드가 메인 스레드이고 스택에 OpenLara의 그리기 함수가 있음 |
| 티베트 산기슭 플레이 중 크래시 (2026-11-15) | NVIDIA OpenGL 드라이버의 화면 출력 스레드 → `dxgi` → `d3d11` → 내장 AMD 드라이버(`amdxx64.dll`)에서 주소 `FFFFFFFFFFFFFFFF` 읽기. 하이브리드 그래픽 노트북의 출력 경로 | 크래시 스레드가 드라이버가 만든 스레드이고 스택에 OpenLara 함수가 없음. 직전 로그는 정상 FPS |

두 번째 경우는 NVIDIA 제어판에서 `OpenLara.exe`의 "Vulkan/OpenGL 표시 방법"을 "네이티브 선호"로 바꿔 그 경로를 피하게 했습니다. 재발 여부는 아직 모릅니다.

## 7. 웹 빌드 확인

```bash
source ~/emsdk/emsdk_env.sh
src/platform/web/build.sh <TR1 게임 폴더> <TR2 게임 폴더>
cd src/platform/web/out && python3 -m http.server 8765 --bind 127.0.0.1
```

- 주소: `http://127.0.0.1:8765/`, 레벨 지정은 `?level=level/2/WALL.TR2`처럼 줍니다. 빌드 스크립트가 데이터 파일을 대문자 이름으로 `out/level/N`, `out/audio/N`에 링크합니다.
- 웹은 파일을 비동기로 내려받아 메모리 파일 시스템에 넣습니다. **동기 `Stream`으로 여는 파일은 미리 내려받지 않으면 없는 것으로 처리됩니다.** 첫 레벨은 내려받은 뒤에 `Game::init`을 부르도록 했고, 텍스처 팩과 라라 얼굴 텍스처는 이 이유로 웹에서 적용되지 않습니다(현재 구조 유지).
- 화면 확인은 헤드리스 Chromium(`--headless=new --use-angle=swiftshader`)을 CDP로 몰아 스크린샷을 찍었습니다. `--screenshot` 옵션은 로딩이 끝나기 전에 찍힙니다.
- 확인한 것: TR1 타이틀, TR1 첫 레벨, TR2 만리장성 화면. 확인하지 못한 것: 키 입력, 소리와 음악, 세이브, 레벨 전환.

| 겪은 오류 | 원인과 처리 |
|---|---|
| `mkdir` 미선언 | `level.h`에 `<sys/stat.h>` 추가 |
| `querySelector '0'` 오류 | 현재 Emscripten은 이벤트 대상에 선택자 문자열을 받음: `"#canvas"`, `EMSCRIPTEN_EVENT_TARGET_WINDOW` |
| 게임패드 assertion | 읽기 전에 `emscripten_sample_gamepad_data()` |
| 엉뚱한 이름의 파일 요청, 범위 밖 읽기 | 메모리 파일 시스템에 없는 첫 레벨을 동기로 열려 함 → 내려받은 뒤 시작 |
| 파일 쓰기 실패 | 시작할 때 `level`, `audio`, `texture`, `video` 폴더를 만듦 |

### 8.7 자막·문자열

- `src/lang.h`는 매크로라 줄 끝에 `\`가 붙고 **마지막 줄에는 없습니다.** 파일이 순수 UTF-8이 아니어서 도구는 surrogateescape로 읽습니다.
- `src/lang/ko.h`는 `#if 0` 안의 UTF-8 원문만 고치면 빌드에 반영되지 않습니다. `src/tools/glyphs/ko_glyphs.py`로 글리프 문자열과 `glyph_ko.*`를 다시 만들어야 합니다. 글리프 순서는 `glyph_ko.txt`가 유지합니다.
- 자막 형식은 `"[ms]대사"`, `@`는 줄바꿈. 싱크 편집은 `src/tools/subtitles/` (serve.py).
- 컷씬 레벨(`data/cut3.TR2` 등)을 직접 실행하면 끝날 때 자동 저장되어 체크포인트가 지워질 수 있습니다.

## 9. 디버깅·테스트 절차

- **세이브 백업이 먼저**입니다. 세이브(Windows `%APPDATA%\OpenLara\tr2\savegame.dat`, Linux `~/.openlara/tr2/savegame.dat`)를 테스트 전에 복사하고, 사용자 동의 없이 바꾸지 않습니다. 테스트가 끝나면 `cmp`로 그대로인지 확인합니다. 하네스는 `HOME`을 스크래치 폴더로 바꿔 실제 세이브를 건드리지 않게 합니다.
- **임시 디버그 코드는 줄 끝에 `// DEBUG_TMP`** 를 붙여 독립된 줄로 넣고, 커밋·배포 전에 `sed -i '/DEBUG_TMP/d'`(macOS는 `sed -i ''`)로 지웁니다.
  - 원래 코드 줄 끝에 태그를 붙이면 그 줄까지 지워집니다.
  - 함수 머리 앞에 끼워 넣을 때 함수 선언을 중복하지 않도록 주의합니다 (`virtual void update() {` 앞 삽입 실수 2회).
- **재현 수단**
  - 명령행(3장): `data/LEVEL.TR2`로 레벨 바로 시작 (d01724f), `--pos=room,x,y,z,angle` (aa16639), `--activate=index,...` (133a5b9).
  - 최신 세이브 로드: `level.h`의 `if (loadSlot > -1 && nextLevel == TR::LVL_MAX)` 앞에 LOADCP 훅 (`loadSlot = saveSlots.length - 1`).
  - 상태 출력: `Lara::update()` 머리에 PROBE 출력, 필요하면 플랫폼 `main`의 `Game::render()` 뒤에서 `glReadPixels`로 프레임 덤프(직접 볼 때는 F12 스크린샷).
  - stdout 버퍼링: Linux는 `stdbuf -oL`로 실행하고, macOS는 `setvbuf`를 넣은 dylib을 `DYLD_INSERT_LIBRARIES`로 주입했습니다. Windows 빌드는 실행 파일 옆 `OpenLara.log`에 바로 씁니다.
- **강제 입력의 한계**: `networkInput`으로 넣은 입력은 `Input::state`를 직접 읽는 코드(스위치, 퍼즐 판정)에는 닿지 않습니다.
- **대조군**: 수정 효과는 끄는 스위치(환경변수)를 임시로 두고 같은 세이브에서 켠/끈 결과를 비교합니다. 8.4의 난수 문제 때문에 반복 실행이 필요합니다.
- **원본 스크립트를 근거로**: TR2의 레벨별 규칙은 `TOMBPC.DAT`에 있습니다(TRosettaStone 11장 구조). 비밀 음악 번호(헤더 SecretSoundID), 레벨 명령(NoFloor, StartAnim, RemoveWeapons/RemoveAmmo, KillToComplete, 시작·보상 아이템), 레벨별 열쇠·퍼즐·퀘스트 아이템 이름을 여기서 읽어 대조했습니다. 문자열은 헤더의 XOR 키로 풀고, 아이템 번호는 1000 이상이 시작 아이템, 미만이 비밀 보상입니다(TRosettaStone은 반대로 적었으나 데이터와 TRX가 이쪽).
- **참조 문서의 틀린 곳**: TRosettaStone 카탈로그는 264번을 '드래곤 폭발 이미터'로 설명하지만 TRX 디컴파일은 지진 객체입니다. 문서 설명과 디컴파일이 다르면 디컴파일을 따릅니다.
- **원인 확인 후 수정**: 로그로 원인을 확정한 다음에 고칩니다 (예: 조준 문제는 trace 경로를 칸 단위로 찍어 문 면 위치를 확인한 뒤 512 여유를 찾음).
- **테스트 위치 함정**
  - `--pos`의 방 번호가 실제와 다르면 라라가 벽 칸 안에 놓입니다(총구 trace가 바로 멈춤). 방 범위(`info.x/z`, `xSectors/zSectors`)를 덤프해 내부 칸을 고릅니다.
  - 칸 경계(1024 배수)에 세우면 총구가 옆 칸(벽)에 들어갑니다. 경계에서 조금 안쪽으로 둡니다.
  - 물속에서는 y를 바닥 높이로 주면 라라가 바닥에 묻힙니다. 물 가운데 높이로 줍니다.
  - 적과 라라의 구역(zone)이 다르면 적이 다가오지 않습니다. 적이 실제로 걸어간 통로에 라라를 둡니다.
- **인벤토리는 하네스로 조작할 수 없습니다.** 인벤토리가 열리면 게임이 멈추므로, "선택된 뒤"는 `usedItem`을 직접 넣어 흉내 내고, "열리는 순간"은 따로 확인합니다.
- **시작 옵션**: `--give=KEY_ITEM_2,...`(열쇠·퍼즐 또는 타입 번호를 인벤토리에), `--activate`는 레벨 시작 1초 뒤에 작동(d1c849f).
- **바닥 덤프의 포털 표시**: `ROOMGRID` 훅에서 `roomBelow != 255`인 칸은 `v방번호`로 찍습니다. 하늘 방에서는 이 칸에 세우면 바로 떨어집니다.
- **보이는 방 확인**: 깜박임은 `getVisibleRooms`의 목록 수·고유 방 수·한도 초과 횟수를 프레임마다 찍어 확인했습니다(VISLOG 훅).
- **입력 주입과 화면 확인**: `networkInput`에 시간대별 입력을 넣는 INPUTS 훅(`"1.5-2:128,4-8:8"`, 값은 `Character::Key` 비트)과 플랫폼 `main`의 SHOTS 훅(지정 시각에 PPM 저장)으로 탑승·주행·사격을 재현했습니다. 적을 바로 쓰러뜨리는 KILLDRV, 라라를 차량 옆으로 옮기는 TOBLACK 같은 일회성 훅도 같은 방식입니다.
- **섞인 diff로 유형별 커밋**: 한 파일의 diff 블록이 서로 얽혀 블록 단위로 나눌 수 없으면, 최종 파일에서 뒤 커밋 몫을 지운 중간본을 만들어 `git update-index --cacheinfo`로 인덱스에 올립니다. 이렇게 나눈 중간 커밋이 뒤 커밋의 정의(예: 사운드 번호)를 써서 단독 빌드가 실패한 적이 있으니, worktree 빌드는 빼지 않습니다.
- **유형별 커밋 나누기**: 한 파일에 여러 유형이 섞이면 `git diff -U0`의 블록을 골라 `git apply --cached --unidiff-zero`로 스테이징합니다(부록 스크립트).
  - **주의**: 앞쪽 블록을 건너뛰고 뒤쪽 블록만 `-U0`으로 올리면 줄 위치가 어긋나 코드가 엉뚱한 곳에 들어갈 수 있습니다(6단계 조명탄 커밋에서 실제로 발생, 최종 커밋이 바로잡아 최종 코드는 정상이었지만 중간 커밋이 빌드되지 않아 다시 만들어 강제 푸시). 안전한 방법은 기준 커밋에서 만든 **임시 worktree에 `-U3` 블록을 골라 `git apply`**(문맥으로 위치를 찾음)하고 커밋마다 빌드하는 것입니다. 푸시 전에 각 커밋을 worktree에서 빌드합니다.
  - 순수 추가 블록은 git이 **새 파일 기준 줄 번호(+쪽)** 로 위치를 정합니다. 앞 블록을 빼고 고르면 +쪽 번호를 다시 계산해야 하며, 이를 빠뜨려 선언이 다른 함수에 들어간 커밋을 만든 적이 있습니다(푸시 전에 되돌려 다시 만듦).
  - 스테이징한 diff는 `git diff --cached -U2`로 앞뒤 문맥을 확인하고, 푸시 전에 `git worktree`로 중간 커밋을 모두 빌드합니다.
- **시작 위치는 바닥 덤프로 고릅니다.** 방의 칸별 바닥 높이를 덤프(`ROOMGRID` 훅: 방의 각 칸 중심에서 `getFloorInfo`)해, 바닥이 있는 칸의 중심과 그 칸의 바닥 높이를 `--pos`에 줍니다. 엔티티 좌표나 적이 지나간 좌표를 그대로 쓰면 벽 칸(바닥·천장 -32512, 카메라가 천장 너머로 올라가 화면이 안 보임)이나 바닥 아래(라라가 땅속에 묻힘)가 되기 쉽습니다. 바캉 수도원과 티베트 고원에서 둘 다 겪었습니다.
- **외부 입력 혼입**: 테스트 중 사용자가 같은 앱 창에 키를 누르면 하네스 로그에 이유 없는 이동이 섞일 수 있습니다. 한 번 이상한 결과는 다시 돌려 확인합니다.

## 부록. 블록 단위 스테이징 스크립트

`python3 stage_hunks.py <파일> list`로 `-U0` 블록을 보고, `python3 stage_hunks.py <파일> 0 3 5:0-32`처럼 블록 번호(또는 순수 추가 블록의 줄 범위)를 골라 스테이징합니다. 커밋할 때마다 번호가 바뀌므로 다시 `list` 합니다.

```python
import subprocess, sys, re
path = sys.argv[1]
diff = subprocess.run(['git', 'diff', '-U0', '--', path], capture_output=True, text=True).stdout
lines = diff.splitlines(keepends=True)
i = 0; head = []
while i < len(lines) and not lines[i].startswith('@@'):
    head.append(lines[i]); i += 1
hunks = []
while i < len(lines):
    h = [lines[i]]; i += 1
    while i < len(lines) and not lines[i].startswith('@@'):
        h.append(lines[i]); i += 1
    hunks.append(h)
if sys.argv[2] == 'list':
    for n, h in enumerate(hunks):
        print('== %d %s' % (n, h[0].strip()))
        for k, l in enumerate(h[1:]):
            print('   %3d %s' % (k, l.rstrip()[:110]))
    sys.exit()
out = []; delta = 0  # added minus removed lines of the hunks taken before, the new positions follow from it
for n, spec in sorted((int(x.split(':')[0]), x) for x in sys.argv[2:]):
    h = hunks[n]
    m = re.match(r'@@ -(\d+)(?:,(\d+))? \+(\d+)', h[0])
    old_start, old_count = int(m.group(1)), int(m.group(2) if m.group(2) is not None else 1)
    body = h[1:]
    if ':' in spec:
        a, b = map(int, spec.split(':')[1].split('-'))
        assert old_count == 0
        body = body[a:b + 1]
    removed = sum(1 for l in body if l.startswith('-'))
    added = sum(1 for l in body if l.startswith('+'))
    new_start = old_start + delta + (1 if old_count == 0 else 0) - (1 if added == 0 else 0)
    out.append('@@ -%d,%d +%d,%d @@\n' % (old_start, old_count, new_start, added))
    out += body
    delta += added - removed
r = subprocess.run(['git', 'apply', '--cached', '--unidiff-zero', '-'], input=''.join(head + out), text=True, capture_output=True)
print(path, 'staged' if r.returncode == 0 else 'FAILED ' + r.stderr)
```
