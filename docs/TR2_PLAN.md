# TR2 구현 계획과 작업 유의사항

`refactor/tr1-tr2-split` 브랜치에서 Tomb Raider 2 원본 데이터를 OpenLara로 돌리며 쌓인 시행착오를 정리하고, 남은 미구현 객체의 구현 계획을 그에 맞춰 보완한 문서입니다.

- 처음 작성: 2026-10-25, `master..refactor/tr1-tr2-split` 커밋 103개 (272f246까지)
- 최종 갱신: 2026-10-27, 1~5단계 완료 (81ed883까지 푸시)
- 미구현 조사: TR2 정규 레벨 19개(컷씬 제외)를 디버그 빌드로 불러, 객체마다 생성된 컨트롤러 클래스를 덤프해 집계
- 다음 세션은 **6장 "다음 세션 인계"** 부터 읽으면 됩니다.

## 1. 현황

TR2 정규 레벨 19개에 등장하는 객체 중 **기본 `Enemy`로 만들어지는 적 17종**과 **기본 `Controller`로 만들어지는 장치·연출 객체 약 12종**이 미구현입니다.

- 기본 `Enemy`는 체력 100으로 제자리에 서 있기만 합니다 (이동·공격 없음).
- 기본 `Controller`는 아무 동작도 하지 않습니다.
- 픽업, 열쇠·퍼즐 아이템, 시크릿, 카메라 타깃(`VIEW_TARGET`), `PUZZLE_DONE`은 기본 `Controller`로 충분하므로 미구현에서 제외했습니다.

진행을 막는 것은 얼음 궁전의 스프링보드·종·징, 티베트 고원의 스노모빌, 드래곤 레어의 마르코/드래곤입니다.

## 2. 작업 원칙

- **원작 동작이 기준**입니다. TRX(GPLv3)는 동작을 확인하는 참고로만 보고 코드를 옮기지 않습니다. 커밋 메시지에 "As the original does"와 원작 함수명(Object_Collision, ItemPushLara, GetHeight 등)을 남겨 근거를 기록합니다.
- **TR1과 TR2 규칙이 다르면 버전으로 분기**합니다 (`level->version & TR::VER_TR1`). TR1 원작과 다른 동작을 TR1에 퍼뜨리지 않습니다 (예: 18d5da1 매복 숨김은 TR2+만).
- **공통 코드는 공통 헤더, 게임 전용은 전용 헤더**: `enemy.h`/`objects.h`는 공용, `enemy_tr1.h`/`objects_tr1.h`, `enemy_tr2.h`/`objects_tr2.h`는 각 게임 전용 (3b88f8e).
- **커밋은 논리 단위로 나눕니다.** 한 커밋은 한 가지 동작 변화와 그 원인을 설명합니다. 메시지는 영어, 마지막 줄에 Co-Authored-By.
- **빌드는 Release와 Debug 둘 다** (`src/platform/osx/build.sh`, `-d`), 배포는 `~/Downloads/TR1`, `~/Downloads/TR2`에 `OpenLara.app`과 `OpenLara-Debug.app`.

### 3.8 디버깅·테스트 절차

- **세이브 백업이 먼저**입니다. `~/Library/Application Support/OpenLara/tr2/savegame.dat`를 테스트 전에 복사하고, 사용자 동의 없이 바꾸지 않습니다. 테스트가 끝나면 `cmp`로 그대로인지 확인합니다.
- **임시 디버그 코드는 줄 끝에 `// DEBUG_TMP`** 를 붙여 독립된 줄로 넣고, 커밋·배포 전에 `sed -i '' '/DEBUG_TMP/d'`로 지웁니다.
  - 원래 코드 줄 끝에 태그를 붙이면 그 줄까지 지워집니다.
  - 함수 머리 앞에 끼워 넣을 때 함수 선언을 중복하지 않도록 주의합니다 (`virtual void update() {` 앞 삽입 실수 2회).
- **재현 수단**
  - 디버그 빌드 명령행: `data/LEVEL.TR2`로 레벨 바로 시작 (d01724f), `--pos=room,x,y,z,angle` (aa16639), `--activate=index,...` (133a5b9).
  - 최신 세이브 로드: `level.h`의 `if (loadSlot > -1 && nextLevel == TR::LVL_MAX)` 앞에 LOADCP 훅 (`loadSlot = saveSlots.length - 1`).
  - 상태 출력: `Lara::update()` 머리에 PROBE 출력, 필요하면 `main.mm`의 `Game::render()` 뒤에서 `glReadPixels`로 프레임 덤프.
  - stdout 버퍼링은 `setvbuf`를 넣은 dylib을 `DYLD_INSERT_LIBRARIES`로 주입해 해결.
- **강제 입력의 한계**: `networkInput`으로 넣은 입력은 `Input::state`를 직접 읽는 코드(스위치, 퍼즐 판정)에는 닿지 않습니다.
- **대조군**: 수정 효과는 끄는 스위치(환경변수)를 임시로 두고 같은 세이브에서 켠/끈 결과를 비교합니다. 3.4의 난수 문제 때문에 반복 실행이 필요합니다.
- **원인 확인 후 수정**: 로그로 원인을 확정한 다음에 고칩니다 (예: 조준 문제는 trace 경로를 칸 단위로 찍어 문 면 위치를 확인한 뒤 512 여유를 찾음).
- **테스트 위치 함정**
  - `--pos`의 방 번호가 실제와 다르면 라라가 벽 칸 안에 놓입니다(총구 trace가 바로 멈춤). 방 범위(`info.x/z`, `xSectors/zSectors`)를 덤프해 내부 칸을 고릅니다.
  - 칸 경계(1024 배수)에 세우면 총구가 옆 칸(벽)에 들어갑니다. 경계에서 조금 안쪽으로 둡니다.
  - 물속에서는 y를 바닥 높이로 주면 라라가 바닥에 묻힙니다. 물 가운데 높이로 줍니다.
  - 적과 라라의 구역(zone)이 다르면 적이 다가오지 않습니다. 적이 실제로 걸어간 통로에 라라를 둡니다.
- **인벤토리는 하네스로 조작할 수 없습니다.** 인벤토리가 열리면 게임이 멈추므로, "선택된 뒤"는 `usedItem`을 직접 넣어 흉내 내고, "열리는 순간"은 따로 확인합니다.
- **디버그 빌드 옵션**: `--give=KEY_ITEM_2,...`(열쇠·퍼즐 또는 타입 번호를 인벤토리에), `--activate`는 레벨 시작 1초 뒤에 작동(d1c849f).
- **바닥 덤프의 포털 표시**: `ROOMGRID` 훅에서 `roomBelow != 255`인 칸은 `v방번호`로 찍습니다. 하늘 방에서는 이 칸에 세우면 바로 떨어집니다.
- **보이는 방 확인**: 깜박임은 `getVisibleRooms`의 목록 수·고유 방 수·한도 초과 횟수를 프레임마다 찍어 확인했습니다(VISLOG 훅).
- **입력 주입과 화면 확인**: `networkInput`에 시간대별 입력을 넣는 INPUTS 훅(`"1.5-2:128,4-8:8"`, 값은 `Character::Key` 비트)과 `main.mm`의 SHOTS 훅(지정 시각에 PPM 저장)으로 탑승·주행·사격을 재현했습니다. 적을 바로 쓰러뜨리는 KILLDRV, 라라를 차량 옆으로 옮기는 TOBLACK 같은 일회성 훅도 같은 방식입니다.
- **섞인 diff로 유형별 커밋**: 한 파일의 diff 블록이 서로 얽혀 블록 단위로 나눌 수 없으면, 최종 파일에서 뒤 커밋 몫을 지운 중간본을 만들어 `git update-index --cacheinfo`로 인덱스에 올립니다. 이렇게 나눈 중간 커밋이 뒤 커밋의 정의(예: 사운드 번호)를 써서 단독 빌드가 실패한 적이 있으니, worktree 빌드는 빼지 않습니다.
- **유형별 커밋 나누기**: 한 파일에 여러 유형이 섞이면 `git diff -U0`의 블록을 골라 `git apply --cached --unidiff-zero`로 스테이징합니다(부록 B 스크립트).
  - 순수 추가 블록은 git이 **새 파일 기준 줄 번호(+쪽)** 로 위치를 정합니다. 앞 블록을 빼고 고르면 +쪽 번호를 다시 계산해야 하며, 이를 빠뜨려 선언이 다른 함수에 들어간 커밋을 만든 적이 있습니다(푸시 전에 되돌려 다시 만듦).
  - 스테이징한 diff는 `git diff --cached -U2`로 앞뒤 문맥을 확인하고, 푸시 전에 `git worktree`로 중간 커밋을 모두 빌드합니다.
- **시작 위치는 바닥 덤프로 고릅니다.** 방의 칸별 바닥 높이를 덤프(`ROOMGRID` 훅: 방의 각 칸 중심에서 `getFloorInfo`)해, 바닥이 있는 칸의 중심과 그 칸의 바닥 높이를 `--pos`에 줍니다. 엔티티 좌표나 적이 지나간 좌표를 그대로 쓰면 벽 칸(바닥·천장 -32512, 카메라가 천장 너머로 올라가 화면이 안 보임)이나 바닥 아래(라라가 땅속에 묻힘)가 되기 쉽습니다. 바캉 수도원과 티베트 고원에서 둘 다 겪었습니다.
- **외부 입력 혼입**: 테스트 중 사용자가 같은 앱 창에 키를 누르면 하네스 로그에 이유 없는 이동이 섞일 수 있습니다. 한 번 이상한 결과는 다시 돌려 확인합니다.

## 4. 보완된 구현 계획

### 4단계: 스노모빌 — 완료

결과: 보트와 스노모빌이 함께 쓰는 `Vehicle`(원작 단위 위치·회전, 벽 밀어내기 `doShift`, 충돌 애니메이션, 30fps 스텝)을 분리했습니다. `Snowmobile`은 네 스키 지점 높이로 앞뒤·좌우 기울기와 낙하를 계산하고, 진행 방향이 차체 방향을 천천히 따라가는 관성 회전, 고속 충돌 피해(속도 차의 절반), 적 치어 죽이기(눈사태는 라라 100 피해), 눈보라(`SnowSprite`), 움직이는 트랙(`SNOWMOBILE_BELT` 메시 1/7을 관절 1에 그림)을 원작대로 합니다. 라라는 옆에서 액션키로 타고, 정지 상태에서 점프+좌/우로 내리며(내릴 자리가 평평하고 공간이 있어야 함), 너무 빨리 떨어지면 손을 놓고 차량은 착지하며 폭발합니다. 탑승은 저장하지 않습니다. 무장 스노모빌 용병(`SkidooDriver`)은 검은 스노모빌이 몸체(AI, 체력 100, step 512/drop 1024)이고 운전자는 같은 애니메이션을 따라 그립니다. 라라가 정면 15° 안에 보이면 두 총을 쏘고(걸어 다니는 라라 50, 탄 라라 10, 5틱 연사음), 치이면 100. 쓰러지면 운전자가 떨어지고 차량이 멈춘 뒤 탈 수 있는 무장 스노모빌(`VEHICLE_SNOWMOBILE_BLACK`, 빨간 것의 애니메이션 사용)이 남습니다. 라라가 그것을 타면 액션키가 가속 대신 사격(매 틱 두 발, 30° 안의 적, 3 피해, 앞을 향하는 총구 섬광)입니다. 사용자가 직접 플레이로 확인했습니다. 치어 죽이기·손 놓기 폭발·넘겨받은 차량의 세이브 로드·보트 재검사는 따로 확인하지 않았습니다.

### 5단계: 중국 구간 보스급 — 완료

결과: 석상 전사(`XianWarrior`/`XianSpearman`/`XianKnight`)는 트리거 전에도 돌 색 석상으로 보이고(조준되지 않음), 깨어날 때 메시가 4프레임마다 하나씩 살아나며, 쓰러지면 마지막 메시부터 다시 돌이 된 뒤 조각나 사라집니다. 창병은 두 창(각 75, 달리며 찌르기 120)을 쓰고, 라라를 죽이면 창에 들어 올리는 처치 연출(이 레벨 LARA_SPEC 상태 2, 예티와 같은 번호)을 합니다. 검병은 한 번에 300을 베고, 라라의 지상 구역이 다르면 날아서(비행 구역, 반짝이와 소리) 건너옵니다. 바르톨리(`Bartoli`)는 라라가 5칸 안에 오면 진동과 반짝이를 모으다 운명의 구체 3개(`SphereOfDoom`, 라라를 밖으로 튕김)를 터뜨리고 드래곤 앞·뒤 몸(동적 엔티티)이 됩니다. 드래곤(`Dragon`, 체력 300)은 3~6칸 거리에서 불(긴 수명의 `FlameStream`)을 뿜고, 가까우면 제자리 회전·할퀴기(250), 닿으면 10. 쓰러지면 11초 뒤 체력 절반으로 부활하며, 그 전에 오른쪽 옆구리에서 액션키로 단검을 뽑으면(LARA_SPEC 상태 7, 레벨의 시네마틱 카메라 270프레임) 녹아 뼈를 남기고 아래의 heavy 트리거를 작동시킵니다. 지진(`EarthquakeTR2`)은 진동과 함께 방의 떨어지는 천장·화염 분사기를 무작위로 작동시킵니다. 사용자가 창병·검병과 드래곤 레어를 직접 플레이했습니다. 단검 이후 레벨 종료, 전투 중 세이브 로드, 구체의 반투명 표현은 확인하지 못했습니다.

### 6.3 테스트 하네스 다시 만들기

스크래치 폴더는 세션마다 지워지므로 새 세션에서 다시 만듭니다. `S`는 그 세션의 스크래치 폴더입니다.

```bash
S=<세션 스크래치 폴더>
mkdir -p $S/TR2run && cd $S/TR2run
for d in audio data music; do ln -sf ~/Downloads/TR2/$d $d; done   # fmv는 일부러 뺌 (레벨 전 영상 건너뜀)
cat > $S/unbuf.c <<'EOF'
#include <stdio.h>
__attribute__((constructor)) static void unbuf(void) { setvbuf(stdout, NULL, _IONBF, 0); setvbuf(stderr, NULL, _IONBF, 0); }
EOF
clang -dynamiclib -o $S/unbuf.dylib $S/unbuf.c
```

`$S/run.sh` (사용법: `FRESH=1 run.sh <로그 이름> <초> <레벨 파일> [게임 인자...]`, FRESH=1이면 디버그 빌드를 새로 복사):

```bash
#!/bin/bash
S=<세션 스크래치 폴더>
LOG=$S/$1.log; SECS=$2; LVL=$3; shift 3
cd $S/TR2run
if [ "$FRESH" = 1 ]; then rm -rf OpenLara.app; cp -R /Users/johnnyb/dvlp/OpenLara/src/platform/osx/build/Build/Products/Debug/OpenLara.app .; fi
DYLD_INSERT_LIBRARIES=$S/unbuf.dylib ./OpenLara.app/Contents/MacOS/OpenLara data/$LVL "$@" > $LOG 2>&1 &
P=$!
sleep $SECS
kill $P 2>/dev/null; sleep 0.3; kill -9 $P 2>/dev/null
exit 0
```

자주 쓰는 임시 훅(모두 `// DEBUG_TMP` 줄로 넣고 끝나면 지움):

- 최신 세이브 로드: `level.h`의 `if (loadSlot > -1 && nextLevel == TR::LVL_MAX) {` 앞에
  `{ static bool once = false; if (!once && getenv("LOADCP")) { once = true; loadSlot = atoi(getenv("LOADCP")); if (loadSlot < 0) loadSlot = saveSlots.length - 1; } } // DEBUG_TMP`
- 엔티티·애니메이션 덤프: `level.h`의 `initEntities()`에서 `initCarriedItems();` 뒤에 환경변수로 켜는 출력 후 `exit(0)`. TR2 타입 번호는 `TR2_TYPES_START`(1000) 오프셋을 반영해 이름을 붙임.
- 상태 출력: `Lara::update()`의 `virtual void update() {` 바로 다음 줄(함수 머리를 중복하지 않게)에 PROBE 출력.
- 화면 저장: `main.mm`의 `Game::render();` 다음 줄에서 `glReadPixels`로 PPM 저장 후 `sips -s format png`로 변환.

### 부록 B. 블록 단위 스테이징 스크립트

`python3 stage_hunks.py <파일> list`로 `-U0` 블록을 보고, `python3 stage_hunks.py <파일> 0 3 5:0-32`처럼 블록 번호(또는 순수 추가 블록의 줄 범위)를 골라 스테이징합니다. 커밋할 때마다 번호가 바뀌므로 다시 `list` 합니다.

```python
import subprocess, sys, re
path = sys.argv[1]
diff = subprocess.run(['git', 'diff', '-U0', '--', path], capture_output=True, text=True).stdout
lines = diff.splitlines(keepends=True)
i = 0; head = []
while i < len(lines) and not lines[i].startswith('@@'):
    head.append(lines[i]); i += 1
hunks = []
while i < len(lines):
    h = [lines[i]]; i += 1
    while i < len(lines) and not lines[i].startswith('@@'):
        h.append(lines[i]); i += 1
    hunks.append(h)
if sys.argv[2] == 'list':
    for n, h in enumerate(hunks):
        print('== %d %s' % (n, h[0].strip()))
        for k, l in enumerate(h[1:]):
            print('   %3d %s' % (k, l.rstrip()[:110]))
    sys.exit()
out = []; delta = 0  # added minus removed lines of the hunks taken before, the new positions follow from it
for n, spec in sorted((int(x.split(':')[0]), x) for x in sys.argv[2:]):
    h = hunks[n]
    m = re.match(r'@@ -(\d+)(?:,(\d+))? \+(\d+)', h[0])
    old_start, old_count = int(m.group(1)), int(m.group(2) if m.group(2) is not None else 1)
    body = h[1:]
    if ':' in spec:
        a, b = map(int, spec.split(':')[1].split('-'))
        assert old_count == 0
        body = body[a:b + 1]
    removed = sum(1 for l in body if l.startswith('-'))
    added = sum(1 for l in body if l.startswith('+'))
    new_start = old_start + delta + (1 if old_count == 0 else 0) - (1 if added == 0 else 0)
    out.append('@@ -%d,%d +%d,%d @@\n' % (old_start, old_count, new_start, added))
    out += body
    delta += added - removed
r = subprocess.run(['git', 'apply', '--cached', '--unidiff-zero', '-'], input=''.join(head + out), text=True, capture_output=True)
print(path, 'staged' if r.returncode == 0 else 'FAILED ' + r.stderr)
```
